- **Real-world CSV shapes produce wrong numbers silently.** Negative-presented costs (MET-3), DD/MM first-of-month dates (MET-4), accounting-format cells (MET-15), "(in $ thousands)" headers (MET-23).
- **The pgvector path has never run in CI or locally.** Both use plain `postgres:17`, and migration 0006 never re-adds vector columns later (API-3, QA-2).

**Release verdict (release-readiness skill):** **NO-GO for demo day** until Phase 0 and Phase 1 of §4 land. The rule breaches in Phase 0 are exactly what judges will probe. Phase 1 contains the failure modes most likely to happen live: a large upload, a double-click on End, a stuck Knowledge page.

## 3. Findings

IDs are grouped by area: MET (metrics and audit), LLM (LLM and court), KB (knowledge base and RAG), API (API, security, infra), VIZ (dashboards), WEB (frontend), QA (test and tooling). Each area is ranked most severe first.

### 3.1 Truth audit and metrics engine (MET)

#### MET-1 · Critical · Valuation figures pass the audit · ✅ Lead-verified
- **Where:** `backend/vicky/audit.py:58-70` (`VALUATION_PATTERNS`)
- **Repro:** `audit_text(text, [arr])` with an ARR figure of 1,286,268 CAD. Each of these passes and cites ARR:
  - `"A pre-money valuation of C$1.3M would be fair."`
  - `"Valuation: $1.3M."`
  - `"A valuation of CAD 1.3M is fair."`
  - `"The company is valued at 13M."`

  Only `"valuation of $1.3M"` is caught.
- **Root cause:**
  - The patterns allow only a bare `[$£€]?` before the digit, so `C$`, `US$` and `CAD ` break the match.
  - `valuation\s+(…|:)` needs whitespace before the colon.
  - `worth|valued at` require a currency symbol.
  - A missed valuation then falls through to figure matching, and the loose tolerance (MET-5) ties it to ARR. With CAD as the default, `C$` is the likely way the model writes money.
- **Fix:**
  ```python
  CUR = r"(?:(?:ca|c|us|a|nz|hk|s)?\$|[£€¥]|\b(?:cad|usd|eur|gbp|aud|chf|jpy)\s?)?"
  rf"\bvaluation\s*(of|at|around|near|should be|would be|could be|is|=|:)\s*(about\s*|around\s*|~\s*)?{CUR}\s?\d",
  rf"\b(pre|post)[- ]money(\s+valuation)?\s*(of|at|=|:)?\s*(about\s*)?{CUR}\s?\d",
  rf"\b(worth|valued at)\s+(about\s+|around\s+|roughly\s+)?{CUR}\s?\d",
  ```
  Also add valuation rules that need no digit (see LLM-2).
- **Regression test:** a parametrised corpus covering `C$`, `US$`, `CAD`, the colon form, `valued at 13M`, and the word forms from LLM-2.

#### MET-2 · High · A forecast fact can crash every context build (`math domain error`)
- **Where:** `backend/vicky/model/truth.py:245-249`
- **Repro:** `build_context(...)` with `Fact(name="burn", value=5000, kind="forecast", status="confirmed")` against negative historical burn raises `ValueError: math domain error`. A forecast of 0 does the same. The founder can enter this fact in the UI (Kind = Forecast), and from then on the dashboard, court and confirm all return 500 for that engagement.
- **Root cause:** `ratio = fact.value / hist.value` can be ≤ 0, and `math.log(ratio)` is unguarded.
- **Fix:**
  ```python
  ratio = fact.value / hist.value
  if ratio <= 0 or ratio > 1.25 or ratio < 0.75:
      sev = 0.95 if ratio <= 0 else 0.45 + min(abs(math.log(ratio)), 1.0) * 0.5
      add(f"gap_{key}", ..., sev, [hist.id])
  ```

#### MET-3 · High · Costs shown as negatives make a loss-making company look profitable
- **Where:** `backend/vicky/model/financials.py:229-250` (`_derive`)
- **Repro:** a CSV row `2025-01,10000,(3000),(4000),(8000),(2000),500000` (Revenue, COGS, S&M, R&D, G&A, Cash) gives:
  - gross margin **129%**;
  - burn **−$27.6K** with runway "Not burning cash";
  - net income **+27,000** (truth: −7,000);
  - the opex mix is silently dropped.
- **Root cause:** cost fields are used as signed values. Accounting files often show costs as `(3,000)` or `-3,000`, and bank-ledger pivots do the same (`AWS -1300`).
- **Fix:** in `build_model`, for `COST = {"cogs", "depreciation", *OPEX_CATEGORIES, "opex.total"}`, if more than half the non-zero values in a column are negative, flip the sign and add a model note: "costs shown as negatives were read as positive".

#### MET-4 · High · Day-first first-of-month dates collapse a year into one month
- **Where:** `backend/vicky/model/loader.py:180-190` (`_dayfirst`), `:133`
- **Repro:** rows `01/01/2025,1000` … `01/12/2025,12000` produce one row `{'period': '2025-01', 'Revenue': 78000}`. Expected: 12 months. This DD/MM/YYYY format is common in Canadian exports.
- **Root cause:** every value is ambiguous (both parts ≤ 12), so `_dayfirst` returns None, the dates are parsed month-first, and all rows merge.
- **Fix:** when nothing is unambiguous, decide by which part varies:
  ```python
  firsts  = {int(m.group(1)) for v in values if (m := _DMY.match(str(v).strip()))}
  seconds = {int(m.group(2)) for v in values if (m := _DMY.match(str(v).strip()))}
  if len(firsts) == 1 and len(seconds) > 1: return True    # 01/MM/YYYY
  if len(seconds) == 1 and len(firsts) > 1: return False   # MM/01/YYYY
  ```

#### MET-5 · High · Claim tolerance is ±50% for round numbers; the spec says ±2% · ✅ Lead-verified
- **Where:** `backend/vicky/model/truth.py:81-100` (`_tolerance`), also used at `audit.py:227`
- **Repro:**
  - `_tolerance(1_000_000, 'cad', 0.02)` returns **500,000**.
  - `check_claim("arr", 1_000_000, …, {arr: 550_000})` returns "matches", even though the founder overstated by 82%.
  - `audit_text("Your ARR is $1M.", [arr=1.29M])` passes.

  The spec is ±2% (VICKY_PLAN:232, TRD:141).
- **Root cause:** integers ≥ 1000 get a precision of `10**trailing_zeros`, so `$1M` gets ±$500K.
- **Fix:** cap the precision allowance relative to the value:
  ```python
  return max(abs(claimed) * rel, min(half, abs(claimed) * 0.05))   # never more than ±5%
  ```
  Alternatively, apply the precision rule only to values written with a suffix (`1.3M`).

#### MET-6 · High · Whole classes of numbers skip the audit
- **Where:** `backend/vicky/audit.py:89-94, 111, 121, 150`
- **Repro:** all of these pass with no finding:

  | Text | Why it slips through |
  |---|---|
  | `"Your ARR is 4.2M and burn is 85K a month."` | no symbol, and the suffix fails `PLAIN_RE`'s lookahead |
  | `"S$4.2M"`, `"CHF 4.2M"`, `"4.2M CAD"` | unknown prefixes; codes are only accepted before the number |
  | `"Net income was -850,000"` | `-` is in a negative lookbehind |
  | `"cash will last 40 months"`, `"runway for the next 40 months"` | "last" and "next" are read as a time window |
  | `"CAC payback is 11 and the burn multiple is 3."` | integers ≤ 12 are ignored |
  | `"2000 customers"` | integers from 1900 to 2100 are ignored as years |

- **Fix:**
  - Add a generic suffix pattern: `(?<![\w.])(-?\d[\d,]*(?:\.\d+)?)\s?(k|m|mm|bn|b|thousand|million|billion)\b`.
  - Build the money prefixes from `currencies._PREFIXES` and `_SYMBOLS`, and allow a code after the number.
  - Allow a leading `-` at the start of text or after whitespace.
  - Drop `last` from the window words unless it is followed by `the`.
  - Don't skip small integers or years when `metric_context()` finds metric ids nearby.

#### MET-7 · High · The "services revenue" attack item is wrong for quarterly data
- **Where:** `backend/vicky/model/truth.py:231-237`
- **Repro:** `sample_context("harbor-labs").attack[0]` says "About 70% of the latest month's revenue isn't recurring." The truth is 9% (633,804 of 695,804), which is under the 12% threshold.
- **Root cause:** `1 - mrr/revenue` divides a monthly MRR (quarter ÷ 3) by a per-quarter total, possibly from different periods. The 70% is also not a Figure, so the audit would block it if quoted.
- **Fix:**
  ```python
  p = ctx.model.latest("revenue.recurring")
  rec, tot = model.value("revenue.recurring", p), model.value("revenue.total", p)
  services = 1 - rec / tot
  ```
  Run this only when both values exist for `p`, and say "latest period" rather than "latest month".

#### MET-8 · High · Any "will" or "plan" in an answer downgrades contradictions to "unsupported"
- **Where:** `backend/vicky/model/truth.py:358`
- **Repro:** `quick_claims("Our ARR is $3M today. Next year we will hire five engineers.")` marks the ARR claim `is_forecast=True`, so `check_claim` returns "unsupported" instead of "contradicts". This feeds the live court (`llm/minds.py:314`). Code-extracted claims win in `merge_claims`, so the LLM cannot correct it.
- **Fix:** run the forecast regex on the claim's own clause only:
  ```python
  clause = _clause(text, m.start(), m.end())
  is_forecast = bool(re.search(r"\b(will|plan|projected|forecast|expect|by 20\d\d|next year|target)\b", clause.lower()))
  ```

#### MET-9 · High · Foreign-currency facts without a rate are labelled in the reporting currency
- **Where:** `backend/vicky/model/metrics.py:99` (`_fact_figure`); `model/context.py:48-63`
- **Repro:** `build_context([], [Fact(name="mrr", value=100000, unit="usd")], {"currency": "cad"}, fx=None)` gives MRR `100000 cad` and ARR `1200000 cad`. The value is wrong by the exchange rate, and the result is a number the engine never actually derived.
- **Root cause:** `convert_facts` correctly keeps USD when no rate exists, but `_fact_figure(..., unit=ctx.unit)` then overwrites the unit. The same thing affects cash, CAC and `net_burn_l12m`.
- **Fix:** if `fact.unit in CURRENCY_UNITS and fact.unit != ctx.unit`, return a `MissingFigure` with the reason "no USD→CAD rate published for {period}". Do the same check before `cash_burn` is used in `_burn_multiple`.

#### MET-10 · Medium · Plan-vs-history checks never fire
- **Where:** `backend/vicky/model/truth.py:141, 242`; forecast facts are renamed at `llm/docs.py:203`
- **Repro:** on the Tidewell sample with `plan.mrr = 129000`, `check_claim("mrr", 129000, …)` returns "contradicts" instead of "forecast_as_fact". There are no `gap_*` attack items.
- **Root cause:** forecast facts are stored as `plan.<name>`, but the lookups use `FACT_ALIASES.get(fact.name, fact.name)`, which stays `plan.mrr`.
- **Fix:** `base = re.sub(r"^(plan|forecast)[._]", "", fact.name); key = FACT_ALIASES.get(base, base)`, in both places.

#### MET-11 · Medium · Growth windows count data rows, not calendar months
- **Where:** `backend/vicky/model/metrics.py:149-153, 176-181, 189-194, 404, 420`
- **Repro:** 14 months of exactly 10% growth with 2024-12 missing gives `cmgr_12m` = 10.88% and `cmgr_recent` = 15.4%. The YoY figure compares Feb 25 with **Jan 24**. The L12M, CAC and burn windows span more than 12 months.
- **Fix:** pick the start period by calendar offset (`start_p = shift(end_p, -months)`). Return a MissingFigure if that period has no data, and use `months_between(start_p, end_p)` as the exponent.

#### MET-12 · Medium · SR&ED or grant credits received in only some months are ignored
- **Where:** `backend/vicky/model/metrics.py:204-206`

#### MET-13 · Medium · Exchange-rate moves show up as NRR and GRR changes

#### MET-15 · Medium · Excel "Accounting" negatives and dash-zeros are lost

#### WEB-1 · High · Open redirect after entering the access code · ✅ Lead-verified (code)
- **Where:** `frontend/components/app/AccessGate.tsx:13-16` (`safeNext`)

  ```ts
    return u.pathname + u.search + u.hash;
  }
  ```

## 5. Checked and found sound

So the next pass doesn't repeat them:

- **Auth and transport:**
  - every route and the WebSocket are gated;
  - the cookie is HttpOnly, SameSite=Lax and Secure in prod;
  - `hmac.compare_digest` is used;
  - CORS allows one explicit origin;
  - JSON-only bodies stop simple-request CSRF;
  - the proxy blocks path traversal.
- **SQL:** all parameterised. The f-string SQL uses whitelisted names only, and tsquery input is sanitised.
- **Secrets:** none in the tree or git history. Both images run as non-root. LF line endings are enforced.
- **Migrations:** ordered, under an advisory lock, tracked, and clean on a fresh DB. The one-active unique index holds under concurrent confirms.
- **Anthropic SDK usage (v1.15):**
  - model ids, `output_config.effort`, thinking, fallbacks and the beta header are valid;
  - `max_tokens` is always set;
  - `cache_control` is on at most 2 blocks;
  - stop reasons (`refusal`, `max_tokens`, `pause_turn`) are handled;
  - parse failures fall back to the offline mind.
- **Viz DSL:** no `eval`/`exec`; dunder names, attribute access and `**` are rejected; recursion is bounded.
- **Uploads:** the zip-bomb and zip-traversal guards hold, encrypted PDFs fail cleanly, a missing tesseract degrades gracefully, chart XML is parsed XXE-safe, and the chunker always terminates.
- **RAG:**
  - builds are serialised;
  - cache keys include the build and `kb_version`, so edits never serve stale chunks;
  - the catch-all offer is single-use and tied to its dashboard.
- **Frontend:**
  - no XSS sinks (react-markdown without raw HTML);
  - no hydration warnings at 1440 or 375px;
  - `useApi` ignores out-of-order responses;
  - the socket reconnects with backoff;
  - no old persona ids are left in `app/`, `components/`, `lib/` or `e2e/`.
- **Metrics on the samples:** the Tidewell, Harbor Labs and services-co figures match `expected.yaml` and FR-1, and divide-by-zero guards hold for every core metric.
